# AI 售后工单辅助台

面向电商商家的售后问答辅助工具：把客户问题拆成**诉求 / 已知事实 / 信息缺口 / 争议点 / 处理建议与依据 / 不确定性**六块，并明确标出**什么时候不能让 AI 自己回答**。

> 这是个人项目，用于演练与求职展示。规则为模拟规则，**不代表任何真实商家的售后制度**，未经真实商家验证、未上线、没有真实用户。

## 现在是什么状态（V3-1，2026-11-21）

**核心不是「生成一段客服话术」，而是「说清这个售后问题现在能确认什么、还缺什么、下一步怎么处理」。**

| 层 | 文件 | 作用 |
|---|---|---|
| 结构化分析 | `analysis.py` | 把一句话 + 规则命中拆成六个模块；事实带来源，缺口分「必须 / 可选」，只报真实出现的矛盾 |
| 识别第 1 层 | `engine.py::_analyze_v1` | 15 条关键词规则；客户原话命中权重是辅助字段的 2 倍 |
| 识别第 2 层 | `llm_classifier.py` | 模型只做意图分类与事实抽取，不写答复；编造规则 ID 归 UNKNOWN |
| 识别第 3 层 | `engine.py::SYNONYMS` | 无密钥 / 模型失败时兜底 |
| 识别第 4 层 | `engine.py::FOLLOW_UP_QUESTION` | 转人工时附一句可直接发出的澄清话术 |

- 规则库：5 类 × 15 条 + 12 个转人工触发词
- 界面：Streamlit，侧边栏可切 auto / rules / llm
- 命令行：`main.py`，默认输出结构化报告，`--brief` 看简版

## 三条产品底线（写进代码，不靠自觉）

1. **已知事实只能来自输入或模型抽取**，每条标来源与核实状态；不生成订单号、物流单号、凭证、金额。
2. **依据只能来自规则库**；规则没覆盖就不给结论，而不是编一条规则。
3. **没发现争议就明说「暂未发现明显争议」**，不为了看起来完整而编一个争议；有矛盾时两边都摆出来，交人工核实。

## 输出只有四类，没有第五类

1. **规则明确 + 信息齐全** → 给处理建议与规则依据
2. **关键信息缺失** → 标出缺什么，区分「必须核实 / 可选补充」，不硬答
3. **双方说法冲突** → 两边都摆出来，交人工核实，不替任何一方下结论
4. **赔付 / 投诉 / 例外承诺 / 规则未覆盖** → 转人工，AI 不独立担责

设计意图：宁可少答，不可乱答。测试里「转人工」不算失败，**错误答复才算**。

再做三条：平台规则优先于商家规则、不假装引用未提供的规定；不连接电商后台、不自动查询订单物流、不自动退款；测试材料优先用虚构或脱敏案例。

## 测试现状（数字都是跑出来的）

| 测试 | 命令 | 结果 |
|---|---|---|
| 结构化验收（六模块 / 不编造 / 缺口分级 / 争议 / 无规则兜底） | `python tests\test_structured.py` | **66/66** |
| 12 条设计用例（不回退） | `python tests\run_tests.py` | **12/12** |
| 6 条换说法三模式对比 | `python tests\run_badcases.py` | rules **0/6** → auto **6/6**，错误答复 0 |
| 模型层单测（假客户端） | `python tests\test_llm_parse.py` | **9/9** |
| 页面冒烟（Streamlit AppTest） | `python tests\test_app_smoke.py` | **8/8** |

诚实说明：

1. 12 条设计用例是照着规则关键词写的，属于「自己出题自己答」，只证明实现与设计一致。
2. 同义词表包含测试句的说法，所以 6/6 不能当泛化能力证明。
3. **模型层还没真跑过**——本机没有密钥，模型路径只用假客户端验证了解析与回落。
4. 「事实抽取」在无密钥时只依赖输入字段，不是模型抽取。

## 怎么运行

**方式一（最省事）**：直接双击 `run.bat`。它会自动用项目自带的 `.venv`（依赖已装好），浏览器会打开页面。

**方式二（PyCharm）**：File → Open → 选 `D:\AI售后辅助` → 打开，然后在底部 Terminal 执行
```
python -m streamlit run app.py
```

**方式三（命令行，最快）**：
```
python main.py --check                          # 三步体检：库、密钥、密钥能不能用
python main.py --open-env                       # 帮你打开 .env 填密钥
python main.py "我买的东西还没发货，我想退款"     # 结构化报告
python main.py --brief "东西坏了"                # 简版输出
python main.py --rules "东西不满意，能退钱吗"     # 只跑关键词，看 V1 原样
```

**配模型密钥（可选，不配也能用，只是跳过模型层）**：

1. 在项目目录跑 `python main.py --open-env`（没有 `.env` 会自动复制一份并打开）
2. 把密钥贴在 `DEEPSEEK_API_KEY=` 的等号后面，不加引号、不留空格
3. 按 Ctrl+S 保存，关掉记事本
4. 跑 `python main.py --check`，三步全 `[OK]` 就成了

`.env` 已被 `.gitignore` 排除，不会被推上 GitHub。

## 已知问题

1. **争议检测是规则化匹配**：只覆盖 4 类「客户说法 vs 订单情况」矛盾，复杂对话冲突还认不出。
2. **缺口分级是启发式**：含「单号 / 时间 / 状态 / 凭证」等关键词的项算「必须核实」，不是按业务影响排的优先级。
3. 同义词表有天花板，且与测试句有重叠，命中率偏乐观。
4. 模型层真实准确率未知（无密钥）。
5. 「补充信息再分析」还没做：现在只有一句澄清话术，没有补充入口。
6. 没有用户测试、没有部署、没有真实客服对话验证。
